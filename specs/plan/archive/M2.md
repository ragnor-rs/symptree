# Implementation Plan

## M2: Triage vertical slice + symptomizer core + clinic-admin panel {#M2}

**Goal:** Ship the patient-facing happy path end-to-end for one pilot clinic, with symptree as the **scheduler of record**. A patient writes their main complaint in a clinic's Telegram bot (RU or KK), an LLM router parses intent + free-form answers, a deterministic decision tree produces a triage conclusion (urgency, recommended specialist, optional tests with prep notes), and — when the conclusion calls for booking — the bot **auto-assigns the first-available internal slot** (computed from the clinic's own doctor schedules) and the patient confirms. A 24h pre-visit reminder + 2h post-visit feedback ping fire automatically. Clinic admins manage doctors (specialist codes, weekly hours, days off), view per-patient symptomizer results, and see/cancel bookings through a **web admin panel** (Vite SPA over a clinic-admin REST surface). Multi-tenant from day one.

The booking architecture is internal (no HIS/HL7 on the critical path) behind a `MedicalDataSource` abstraction whose only M2 implementation is the `INTERNAL` source — HL7v2/CRM sources are additive later (FR-TNWP9R/FR-2VQ7CA, M3). Re-scoped 2026-06-11: replaces the operator-assisted booking (archived FR-4GCYJK) + in-process HL7 mock (FR-TNWP9R → M3) of the prior M2 plan.

**Prerequisites:** M1 complete (gradle skeleton + bot/backend scaffolds + gate-passing build).
