## Requirement

Ship the data layer + deterministic walker for symptomizer decision trees. The catalog stores versioned, multilingual JSON trees per the schema in technical-spec.md § 2.2 (`text: {ru: ..., kk: ...}` nested objects). The walker is a pure function `(algorithm, current_node_id, picked_option_value) → next_node_id_or_conclusion` — no I/O, no state. The repository ships one synthetic demo tree; clinical trees are operator-supplied content.

This FR is consumed by FR-PWVTT4 (session + LLM router) and indirectly by FR-W3WDWH (Telegram bot — every reply originates from a walker step).

References: requirements.md § 2.2 (i18n); technical-spec.md § 2.1 (`algorithms` schema), § 2.2 (tree JSON), § 4.1 (walker as pure function).

## Acceptance Criteria

- AC-KT4697.1: `algorithms` + `clinic_algorithms` tables exist matching technical-spec.md § 2.1; migration `database/02-migrate-algorithms.sql` applies cleanly.
- AC-KT4697.2: An `Algorithm` Kotlin model deserializes from the JSON schema in technical-spec.md § 2.2. Every text-bearing field (`metadata.name`, every node's `text`, every option's `label`, every conclusion's `diagnosis`/`action`) is a `Map<String, String>` keyed by ISO language code.
- AC-KT4697.3: An `AlgorithmIngestionValidator` validates a tree before insertion. It rejects (with a structured error naming the offending node) any tree where: (a) `entry_point` does not reference an existing node, (b) any option's `next` references a missing node, (c) any text-bearing field is missing a language present in the clinic's `allowed_languages` (validation is invoked per-clinic-enable, not per-store; the algorithm itself ships with all M2-supported languages and is validated at ingestion against the union RU+KK).
- AC-KT4697.4: A `Walker` pure function takes `(Algorithm, currentNodeId: String, pickedOptionValue: String)` and returns a sealed `WalkResult` of either `WalkResult.NextQuestion(QuestionNode)` or `WalkResult.Conclusion(ConclusionNode)`. The function has no I/O, no `Clock`, no mutable state.
- AC-KT4697.5: Calling `Walker.walk` with an invalid `currentNodeId` (not in the tree) throws `IllegalAlgorithmStateException` (typed). Calling with an `optionValue` not in the current node's option set throws `InvalidOptionException` (typed). These are the LLM-validator's hooks for catching hallucinations.
- AC-KT4697.6: The shipped demo tree validates against the multilingual schema. Trees are seeded into the database by `AlgorithmSeedLoader.seed(...)` called from `CoreApp.main` after `MigrationRunner.run()` so a fresh DB has them after migrations. The shipped list is `AlgorithmSeedLoader.KNOWN_ALGORITHMS`.
- AC-KT4697.7: A data-driven test walks every node of every shipped algorithm exhaustively. For each entry → conclusion path, the test asserts the walker terminates and the conclusion is well-formed (urgency in `{emergency, urgent, routine, self_care}`; specialist either null or a string; `clinic_action` in the expected set).

## Technical Design

Builds on technical-spec.md § 2.2 + § 4.1. Specifically:

- **Module layout:** `core/src/main/kotlin/com/symptree/core/symptomizer/{Algorithm,Walker,AlgorithmIngestionValidator,AlgorithmSeedLoader}.kt`. `Algorithm.kt` carries the sealed `Node` + `QuestionNode` + `ConclusionNode` + `Option` types co-located with the top-level `Algorithm` data class (single file because they share serializer wiring).
- **Sealed node hierarchy:**
  ```kotlin
  sealed interface Node { val id: String }
  data class QuestionNode(override val id: String, val text: I18nText, val options: List<Option>) : Node
  data class ConclusionNode(
      override val id: String,
      val urgency: Urgency,
      val diagnosis: I18nText,
      val action: I18nText,
      val specialist: String?,
      val tests: List<String>,
      val additionalTests: List<String>,
      val preparation: Map<String, I18nText>,
      val clinicAction: ClinicAction,
      val followUpDays: Int?,
  ) : Node
  enum class Urgency { EMERGENCY, URGENT, ROUTINE, SELF_CARE }
  enum class ClinicAction { BOOK_APPOINTMENT, BYPASS_APPOINTMENT, RECOMMEND_PHARMACY, RECOMMEND_SELF_CARE }
  typealias I18nText = Map<String, String>
  data class Option(val value: String, val label: I18nText, val next: String)
  ```
- **Walker:**
  ```kotlin
  sealed interface WalkResult {
      data class NextQuestion(val node: QuestionNode) : WalkResult
      data class Conclusion(val node: ConclusionNode) : WalkResult
  }
  object Walker {
      fun walk(algorithm: Algorithm, currentNodeId: String, pickedOptionValue: String): WalkResult
      fun entry(algorithm: Algorithm): QuestionNode  // returns the entry-point node
      fun availableOptionValues(algorithm: Algorithm, currentNodeId: String): Set<String>  // helper for the LLM validator
  }
  ```
- **Ingestion path:** `AlgorithmRepo.insert(algorithm: Algorithm, ingestedBy: String)` validates the tree then writes to Postgres. Loading is `AlgorithmRepo.findByKeyAndVersion(key, version)`. (`AlgorithmRepo.listEnabledForClinic(clinicId)` — clinic-scoped enablement lookup — is deferred to FR-PWVTT4, the first consumer.)
- **JSON deserialization:** `kotlinx.serialization` with a custom deserializer for `Map<String, String>` text fields (the existing default works since strings are language-keyed records).

## Testing

Per testing-spec.md. Specifically:

- Unit tests for `Walker` — every public function, every error branch (`IllegalAlgorithmStateException`, `InvalidOptionException`).
- Unit tests for `AlgorithmIngestionValidator` — happy + every rejection branch (bad entry_point, dangling `next`, missing language).
- Integration test for `AlgorithmRepo` — Testcontainers, CRUD + clinic-enable wiring.
- The exhaustive-walk test per AC-KT4697.7 lives in `src/test/kotlin/com/symptree/core/symptomizer/AlgorithmExhaustiveWalkTest.kt` and iterates `algorithms/*.json` fixture files.
- i18n: every shipped algorithm has both RU and KK for every text field — the ingestion validator catches missing languages; an additional test sweeps the fixtures and asserts no `[needs translation]` markers in any shipped algorithm.

## Notes

- **Shipped algorithms** — the repository ships `symptom_demo_adult` only: a synthetic tree whose text is placeholder content, covering every `Urgency` and `ClinicAction` value so it doubles as the schema reference. Clinically-meaningful trees are authored and reviewed by the operator, not shipped here.
- The legacy data uses opaque `W1`/`W2`/`Z16`/`G` answer-node IDs. The ported trees rename these to semantic IDs (e.g., `conclusion_food_injury`, `conclusion_diphtheria_suspicion`) for clarity. Mapping table for traceability lives in the porting script.
- Editing tools (clinic-side algorithm authoring UI, version diff viewer) are out of scope for M2.
- `clinic_algorithms` table is also created by FR-M3WYNS migration; the cross-FR dependency is documented in M3WYNS.
